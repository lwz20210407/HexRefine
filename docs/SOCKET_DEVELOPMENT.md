## Later verified increment: mapped fillet and compact core

The earlier radial sweep cannot resolve the near-horizontal fillet tangent
by indiscriminate axial refinement: a tested angle-clustered variant gave
corner SJ 0.1294 and was rejected. The default legacy topology was preserved.
The opt-in `head_mapping: "fillet_blocks"` instead uses three mapped quarter-
disk meridian patches, ring extrusion and matching adjacent annular blocks.
Its Python mapping follows the project's own `circularCorePoint` TS algorithm.
All interfaces share nodes; it is not merely a surface representation.

`core_mapping: "graded_2to1_compact"` uses a six-quad/three-interior-node
paired patch, versus the retained twelve-quad/nine-node default. Both have
identical eight-vertex boundary partitions. Whole-section and actual saved-CAD
socket tests check unchanged fine side boundaries and discrete volume.

## Generation preflight

`tools.bolthex.socket_plan` computes exact topology counts without allocating
whole-body 3D cells or writing K/INP. It verifies source hashes and rejects an
element budget before doing the expensive boundary integral. A compatible
budget then checks the same 1e-4 CAD-volume rule. Both positive and rejected
CLI paths were exercised: predicted 818,112 H8 equals the actual result.

```powershell
python -B -m tools.bolthex.socket_plan CAD_DIRECTORY --seeds SEEDS_JSON --maximum-elements 1000000
```

Exit 0 means accepted for allocation, not final mesh acceptance. Exit 2 is
an explicit budget/volume rejection. No SJ, face matching or solver certificate
is issued by preflight. Fine fillet block allocation also has an internal
five-million-cell bound; original MeshSeeds positional argument order stays.

New code plus the native probe is covered by 75 fast tests (66 passed / 9
optional skips); nine socket/fillet tests with saved CAD enabled passed
separately (four exercise real CAD), followed by two saved-CAD
count/interface assertions. Full TS and slow eight-case CAD reconstruction
were not rerun. Local logs retain a failed scratch image-export manifest and
its corrected successful retry; neither changed the accepted source mesh.

## Native CAD exchange remains open

Two additional host experiments were run, not merely inferred:

- `OptimizeforCAD=off` yielded the same native STEP volume and bounding drift
  as default export; no fix.
- `*geomimport step_ct ... CleanupTol=0.0000001`, following installed batchmesh
  Tcl conventions, re-exported as zero solids / 174 faces; precise volume
  integration failed. The setting was rejected, not made the product default.

Thus the new K/INP fidelity result does not imply a newly accepted exact-CAD
HM. Earlier diagnostic native HM remains explicitly diagnostic. Evidence is
in `socket-local/fidelity/native-variants.json` and actual LSPP/INP-section PNGs.

A subsequent direct HM probe separates internal geometry from STEP export:
`hm_getvolumeofsolid` reports 699.719658159 mm^3 versus source 699.719619882,
about 5.47e-8 relative. Nevertheless, 10 of 241 source-surface witnesses
queried through `hm_findclosestpointonsurface` exceed 2e-6 mm; maximum is
3.3399108e-5 mm, at thread surfaces. Four deliberately off-surface controls
match independent trimmed-CAD distances within about 3.5e-13 mm. Thus an
untrimmed-plane false match is not hiding this sampled failure. The remaining
deviation may involve geometry conversion or closest-point query accuracy;
these finite tests do not prove either cause or global BRep equivalence.

`tools/hypermesh_geometry_probe.py` now implements this as a bounded reusable
read-only diagnostic. It verifies input hashes and source point distances,
requires controls, caps references at 4096 points and host time at 600 seconds,
and refuses partial/duplicate/failed output. The actual socket case returns
exit 2 with a negative report; no product acceptance gate is changed. Example:

```powershell
python -B -m tools.hypermesh_geometry_probe INPUT_HM SOURCE_STEP REFERENCES_JSON NEW_OUTPUT --hmbatch HMBATCH_EXE
```

Exit 0 means only finite sampled witnesses passed, never exact-CAD or complete
product acceptance. K/INP mesh generation still has no HyperMesh runtime need.

## Reproduction

Use the existing CAD Python environment with build123d/OCP and meshio and an
explicit Node executable. `fixtures/socket-M6` must contain independent
`model.step` and its hash-bound `cad-report.json`. Output must be a new directory.

```powershell
python -B -m tools.bolthex.socket_dev FIXTURES NEW_OUTPUT --node NODE --profile feature
python -B -m tools.bolthex.socket_dev FIXTURES EXISTING_OUTPUT --measure-only
```

`--measure-only` checks source hashes and reads the existing INP without a new
large generation. It writes separate `feature-resolution.json` evidence.
The feature profile caps generation at 200,000 H8 / 64 MiB artifacts; native
transfer caps its K at 32 MiB. Smoke caps at 10,000 H8 / 2 MiB. Neither mode
relaxes corner SJ >=0.15 or positive Gauss Jacobians. Fidelity acceptance
retains CAD-volume <=1e-4, node witness <=2e-6 mm and face probes <=0.02 mm.
